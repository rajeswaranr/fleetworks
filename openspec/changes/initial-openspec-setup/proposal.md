## Why

The repository now has a structured OpenSpec workflow so future FleetApp changes can be planned with clear intent, reusable spec artifacts, and BDD-style acceptance criteria. This reduces ambiguity during implementation and gives the team a repeatable process for changing the app.

## What Changes

- Add OpenSpec project scaffolding under the repository so planning artifacts live with the codebase.
- Create an initial change entry for the OpenSpec setup itself so future work can follow the same structure.
- Add an initial BDD-style spec that captures the expected planning workflow for future FleetApp changes.

## Capabilities

### New Capabilities
- openspec-setup: establishes a repo-local change planning workflow for proposal, design, specs, and tasks.

### Modified Capabilities
- None.

## Impact

This change affects planning artifacts under the OpenSpec folder and does not alter runtime application behavior.
